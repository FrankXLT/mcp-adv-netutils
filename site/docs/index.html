    Getting Started

    Docker & Linux Deployment

    Single-binary CGO_ENABLED=0 deployment over local --stdio or native Go --http with zero Node.js or supergateway.

    The multi-stage build compiles a static CGO_ENABLED=0 pure-Go binary into a single-layer Alpine runtime image measuring 41.5 MB unpacked (11.4 MB compressed). Using RUN --mount=type=bind and setcap cap_net_raw+ep /usr/local/bin/mcp-adv-netutils avoids duplicating the binary across layers while granting raw ICMP/ARP socket privileges to unprivileged USER netutils.

    Container & Native Go Quickstart

    # Local --stdio mode (zero open ports, zero secrets)
docker run -i --rm ghcr.io/frankxlt/mcp-adv-netutils:latest --stdio
# Static CGO_ENABLED=0 build & HTTP + Cron + /web startup (+ offline tests: go test -race ./...)
CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -trimpath -tags netgo -o mcp-adv-netutils .
./mcp-adv-netutils --http --http-addr=:8000 --data-dir=./data --watchlist=./watchlist.yaml

    Docker Compose Pattern

    Grant NET_RAW for ICMP, path MTU, and ARP probes and mount /data for persistent SQLite storage. On older container kernels (such as Synology DSM 4.4), omit runc exec container healthchecks and monitor GET /healthz externally.

    services:
  mcp-netutils:
    image: ghcr.io/frankxlt/mcp-adv-netutils:latest
    restart: unless-stopped
    init: true
    cap_add: [NET_RAW]
    environment: [PASS_HASH=${PASS_HASH}, PATH_SECRET=${PATH_SECRET}, LAN_MCP_TOKEN=${LAN_MCP_TOKEN}]
    command: ["--http", "--http-addr=:8000", "--data-dir=/data", "--max-store-mb=256", "--watchlist=/app/watchlist.yaml"]
    volumes: ["mcp_netutils_data:/data"]
    ports: ["8000:8000"]

    Operator Console

    Network Studio (/web & ./demo/)

    Interactive browser console with Apache ECharts SVG graphs, Saved Destinations, goal-grouped checks, and side-by-side Past Run comparisons.

    Open /web from any desktop, tablet, or phone browser—or preview offline sample fixtures in the Live Demo (?demo=1)—across four themes (Pure White, Warm Paper, Dark, Dark Paper) and two display densities (Comfortable / Compact).

    Workspace Highlights

    • Interactive KPI Triage Cards: Clickable, keyboard-accessible summary cards display 24h Uptime % (— when no scheduled checks exist yet), Active Problems, Saved Destinations, and Saved History Size, jumping directly to the corresponding section.
    • Pinned Destinations & Above-the-Fold Quick List: Favorite targets appear beside + Add Destination and Scan Pinned at the top of Checks, backed by a compact desktop Saved Destinations list directly beneath Run a Check and the full table below.
    • 4 Goal Category Filters: Filter Check Type cleanly across Path & Ping, Web & DNS, Ports & Host, and Wake with context-aware fields for Port Group, Wake MAC chips, and a direct jump link to full subnet scans in Local Network.
    • Apache ECharts SVG Visualizations (renderer: 'svg'): Renders crisp theme-aware path latency & packet-loss whiskers, HTTP/TLS response timing waterfalls, DNS resolver comparison bars, and 24h / 7d / 30d uptime & response-time timelines.
    • Chart / Table Toggle & Export Copy: Flip any result card or past-run view between Chart and Table modes, and copy formatted Markdown with Copy Summary or tab-separated rows with Copy Data (TSV).
    • Local Network Inventory: Search devices by name, IP, MAC, or vendor, choose a comparison baseline, and filter All, Physical Hardware, Containers & VMs, and Changed vs. Baseline with inline response bars and 1-click Ping, Check Ports, Wake, and Save actions.
    • Schedule & History with Past Run Drawer (<dialog>): Inspect 24h / 7d / 30d timelines, enable automated 5-minute monitoring via + Enable 5-Min Monitoring, or click any row in Past Check Runs to open a native modal drawer with Run Again & Compare.

    MCP & CLI Terminal Output

    Three-Tier ASCII formatting (default, quick, rich) and compact json scoped strictly to MCP clients and CLI terminals—while /web renders Apache ECharts SVG graphs and structured tables.

    Browser operators in Network Studio (/web) inspect interactive Apache ECharts graphs, sortable tables, and Markdown/TSV exports. For conversational MCP clients and terminal runs (including --run-watchlist-once), pass the style parameter to match the caller viewport:

    styleWidth / CapFormatting ContractBest Target Client
    default72 cols exactSingle-line header split, severity-sorted rows, and footer job_idChat panes, IDE terminals, 900px tablets
    quick≤ 40 colsBorderless compact lines with zero mid-row wrappingFolded 390px phones and mobile chat
    rich76 cols boxedDouble-line TUI frame, sparklines, 30d health bar, and status legend1440px+ desktops and CLI postmortems
    json< 18.5 KBFAIL → WARN → OK sorted rows; compacts OK rows first if cappedAutomated MCP/CI pipelines and /web API
    Verbatim Display Rule: When displaying MCP terminal cards in chat, wrap default, quick, and rich output verbatim inside a fenced text code block so markdown engines never reflow fixed columns.

    To inspect an older incident at a different width over MCP without re-sending packets, call render_run_digest with the archived job_id and desired style.

    Operations & Security

    Cron Watchlist & 30d Retention

    Scheduled background checks escalating after two consecutive failures, backed by bounded 30-day SQLite WAL storage.

    mcp-adv-netutils embeds robfig/cron/v3 (with SkipIfStillRunning overlap protection) to execute watchlist.yaml and synced dest_<id> Saved Destination schedules in --http mode, or once on demand via --run-watchlist-once for external systemd timers.

    • Two-Failure Alert Threshold: A single non-OK check records a soft pending state without firing an alert; status escalates only after >= 2 consecutive failed checks.
    • 30-Day Job Archive (netutils_jobs.db): Pure-Go SQLite WAL storage (modernc.org/sqlite, read queries via ?mode=ro) persists every manual, MCP, Saved Destination, and scheduled check with explicit expires_at timestamps.
    • Bounded Storage Retention: Granular healthy */5m ticks compact across 7d → 30d while failures keep full diagnostic payloads; an hourly TTL reaper runs PRAGMA incremental_vacuum and enforces --max-store-mb 256.

    Default watchlist.yaml Structure

    jobs:
  - id: wan-canary-ping
    schedule: "*/5 * * * *"
    tool: recipe_diff_ping
    target: "1.1.1.1"
    enabled: true
  - id: wg-mtu-check
    schedule: "*/15 * * * *"
    tool: mtu_path_probe
    target: "1.1.1.1"
    enabled: true
  - id: split-dns-diff
    schedule: "0 */6 * * *"
    tool: recipe_diff_dns
    target: "example.com"
    enabled: true
  - id: edge-http-diff
    schedule: "0 */6 * * *"
    tool: recipe_diff_http

    Operations & Security

    Security Architecture

    Five fail-closed defense layers isolating remote doorways, LAN-only sockets, browser APIs, target CIDRs, and container privileges.

    LayerControlMechanism
    Layer 130-Minute PASS_HASH DeadboltSHA-256 + voice normalization + crypto/subtle.ConstantTimeCompare; 30m auto-relock and immediate lock_netutils
    Layer 2Two-Doorway SetupRemote /{PATH_SECRET}/mcp + /web vs LAN /lan/{LAN_MCP_TOKEN}/mcp & /sse rejecting forwarding headers and non-RFC1918 peers
    Layer 3/web/api/* Anti-CSRF & RebindingStrict same-origin Origin checks and allowlisted Host header validation
    Layer 4Central TargetGuard & CLI --DNS-resolved CIDR checks (--allow-cidrs / --deny-cidrs), mandatory 169.254.0.0/16 block, no-shell -- separation
    Layer 5Unprivileged RuntimeUSER netutils, minimal cap_net_raw+ep binary capability, runtime-only secret env vars
    Metadata & Secret Hygiene: Cloud instance metadata space 169.254.0.0/16 is unconditionally blocked regardless of allowlist flags, and PASS_HASH stores only a 64-character hex SHA-256 digest—never a plaintext passphrase.
